# _Meta/ — Vault Operations

While `_Schema/` defines **what notes look like**, `_Meta/` defines **how the vault is run** — editorial policy, workflow, conventions, and audit trails.

## Files

| File | Purpose |
|---|---|
| `Editorial Standards.md` | Neutrality, citation, perspective-labeling, stance discipline |
| `Source Tier System.md` | T1–T5 source reliability tiers with concrete examples |
| `Curation Workflow.md` | How a note moves stub → draft → reviewed → archived |
| `Style Guide.md` | AI-optimized writing — atomic notes, structure, length, register |
| `Git Commit Conventions.md` | Commit message format and types |
| `Session Log.md` | Append-only machine-readable record of every AI session's work |
| `Curation Backlog.md` | Open research tasks any agent may pick up |

## Reading order for a fresh agent

1. `Editorial Standards.md` — what we will and won't say
2. `Style Guide.md` — how to say it
3. `Source Tier System.md` — how to weight sources
4. `Curation Workflow.md` — the lifecycle of a note
5. `Git Commit Conventions.md` — how to record changes
6. `Session Log.md` (read the last few entries) — what's been happening
7. `Curation Backlog.md` — what needs doing
